# POD选图

按用户已有输入选择起点。关键词从第 1 步开始，参考图或以图搜图结果从第 2 步开始，已经选好的可制作素材直接进入第 3 步。用户只要求找图或预览时，按要求交付对应阶段。

## 1. 查询竞品并等待选图

在skill目录运行，脚本和输出路径按实际位置填写：

```sh
node scripts/sellersprite_browser.cjs search --query 'pet house' --out /absolute/run
```

入口通过 Amazon.com 匿名查 ASIN，再用卖家精灵批量查销量和主图，按父体近 30 天销量降序展示全部有效候选。默认搜索第一页，配送国为美国。配送参数见 [竞品查询](references/sellersprite-access.md)。

展示 `products.html`，用户可回复编号或导出选择JSON。将选中编号与ASIN保存为 `selected-products.json`，**等待用户选择后再继续**。

分页、候选范围与错误处理见 [竞品查询](references/sellersprite-access.md)；授权或环境问题见 [环境与人工接管](references/environment.md)。

## 2. 在花瓣以图搜图并筛选

按已选ASIN从排序数据取对应主图，逐张原样提交花瓣“以图搜索”。每张检索完成后随机冷却4–6秒，再提交下一张；入口在连续命令间共享频控并串行执行图片搜索。记录参考图、来源ASIN、图片摘要和实际结果页；多选时分别检索，再合并去重。具体命令及花瓣会话要求见 [花瓣检索与初筛](references/huaban-workflow.md)。

用候选详情页「查看大图」下载的文件做筛选。按主体、绘画风格、配色、构图和装饰元素判断，区分图案与商品外形、商标、文字、包装及摄影背景。可从合适结果继续扩展相似图和推荐画板，保留来源、筛选理由和授权状态。选定后直接沿用本地大图做后续处理。

## 3. 制作效果图并保存设计

按 [PODQHY 制作流程](references/podqhy-workflow.md) 执行。先明确实际产品、需要的变体和选定素材，沿用用户已给出的宽高比。用户明确让你自行找图测试时直接选择合适素材。

1. 检查选图阶段保存的花瓣大图。满版重复纹样先从干净的同款位置补回，再用 AI 局部修复剩余掩码。孤立的小块水印可先用局部修补。按 [水印处理](references/podqhy-workflow.md#水印处理) 检查整张原尺寸图和纹样接缝。
2. 共享上传图的宽、高均以 **2000 px 为下限**。不足时等比补足，两边达标时保留尺寸。各设计面按实际模板适配。用 `artwork-manifest.json` 的 `upload_plan.file` **只上传一次**，放好首面后点“复制至 → 所有（位置居中）”。逐面检查铺满、构图和裁切。
3. [导出实际列表的全部视角](references/podqhy-workflow.md#全部效果图导出)，只保留产品渲染画布。最终效果图宽、高均至少 **2000 px**。不足时按指定比例补足，未指定则以 2000×2000 为起点。已达标且符合指定比例的图片直接保留。
4. 确认当前设计与导出时一致，然后点顶部“保存”，用与图案相符的名称保存并核验站点成功提示。用户明确要求只预览时在出图后交付。此流程止于保存设计。

像素扩充优先用 Python 等比放大。按目标尺寸检查细节，只有清晰度仍影响使用时才尝试 AI 超分，核对内容、颜色和接缝再选用。详细判断见 [像素扩充与超分复核](references/podqhy-workflow.md#像素扩充与超分复核)。

## 交付

结果放在当前项目 `reports/pod-selection/<任务>/`。竞品阶段交付 `products.html` 和排序数据；素材阶段交付 `gallery.html`、`candidates.json`、`report.md`；制作过程保留模板数据、来源记录、去水印记录（如有）、共享上传图、逐面 PNG、处理清单和对比图。最终交付 `final-effects/` 中按用户比例处理的全部视角纯效果图、`effects-manifest.json`、`effects.html` 及 `design-save.json` 的设计名和保存状态。交付图片数与实际视角数一致，像素宽高比符合用户输入；缺图或保存未核验时明确说明，不标记整套完成。仅生成本轮已完成阶段的文件。参考素材默认标记“灵感参考，授权待核实”。
