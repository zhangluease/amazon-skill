# 日本亚马逊 Listing 生成

将用户关键词文件与本品事实整理为日文上架文案和图片制作策划。固定 `site=JP`、`listing_language=Japanese`、`listing_language_code=ja`；策划说明、筛词理由和报告用中文。模型负责语义判断与写作，脚本负责导入、逐词记录、引用和数量检查、后端调用及报告渲染。

## 新版字段分工

只生成新版「标题＋标题下灰字小标题（Item Highlight）＋五点」结构，不提供旧版长标题方案。标题 ≤75 字符、小标题 ≤125 字符，均含空格；日本站非媒体类依据及新版页面参考见[日文写作要求](references/japanese-listing.md)。

- 标题：保留完整品名与配件身份，在自然日语中优先前置高相关、高流量的可用搜索词；普通材质、尺寸不占标题。品牌与确有识别必要的型号按真实资料保留，不为凑满 75 字符塞规格或堆词。
- 小标题：优先交代已确认的几枚装／几个装和套装组成，再补标题未覆盖的相关词或用途。数量未知不猜，材质与尺寸交给五点正文。
- 五点：每条以相关流量词构成简短自然标签或首句，再解释该主题对应的真实卖点；材质、尺寸、适配、使用与保养等在正文展开。替换滤网等适配型耗材采用下述机型清单结构，可连续多条写不同组的适配机型，不强行为五条安排五个不同主题。

### 适配型耗材的五点结构

本品为替换滤网等依赖机型选择的配件／耗材时，读取[适配机型清单规则](references/compatibility-lists.md)。完整列出全部已确认机型是本品购买信息的必保项，不受关键词流量高低影响。缺适配资料时登记 compatible_models 的 unknown 空清单及待补缺口，不以几条泛卖点冒充已完成机型清单。

- 画像用 `facts.field=compatible_models` 保存完整型号数组、来源与确认状态，可按来源／系列分组。未知或冲突项另留待核实，竞品清单不能直接转成本品事实。
- 通常用 2–3 条五点按系列分组列全机型，短名单可用 1 条；剩余条目承接本品型号、包装、材质尺寸、清洗和更换。开头自然结合相关搜索词与「対応機種①／②／③」等标签，允许为机型组连续使用适配主题。
- 保留每个型号的完整后缀；不以「HD-RXシリーズなど」、省略号、范围或只列热门机型代替完整名单。不得把完整名单仅移到长描、图片或附件而让五点缺失。
- 已确认且在对应五点正确引用的型号及分隔符，单独于普通文案的 250／1250 字符编辑预算计数；上架原文不删减，仍以实际类目与后端结果验收。真实字段限制冲突时保留完整稿和失败状态，不静默删型号或改写校验结果。

以上词位安排是用户确认的移动端运营策略；字符上限与可搜索性有官方依据，不把策略写成 Amazon 已公开的算法权重。高流量不能覆盖相关性、事实与完整品名约束。

## 输入与边界

- 输入关键词表格与本品名称、图片、规格、用途和限制。品牌、必保词、禁用词、包装清单和本品 SKU/ASIN按用户已有资料记录；缺失项不补造。
- 接收多个 XLSX/CSV/TSV，包括卖家精灵导出和 `amazon-jp-keywords` 的 `keywords.xlsx`／`seed-keywords.xlsx`；可自动识别「日文关键词」「易逊月搜索量」「易逊流量占比」。保留全部原始列与来源，不将 ABA 排名当作月搜索量。
- 本技能不执行云端扩词。只有 ASIN 或种子词、尚无词表时，先整理本品资料并说明需要词表；用户要求同时找词时先用 `amazon-jp-keywords` 交付词表，再进入本流程。
- 关键词采集阶段保留的 Amazon 联想词，在生成 Listing 时仍须核对本品身份、完整购买意图与事实依据；采集保留不表示允许写入文案。禁止把竞品规格、QA 或示例资料当成本品事实。
- 每次任务只处理一个实际销售商品，生成一套文案及图片／A+ 策划。多个商品分别创建独立任务目录，各自使用对应资料。

## 执行顺序

读取[完整工作流](references/workflow.md)后执行。`SKILL` 是本技能绝对路径，`RUN` 是 `reports/jp-listing/` 下新建的独立任务目录。

1. 用 `listing_environment.py init` 创建任务；按[数据契约](knowledge/data_contract.md)建立输入快照与产品画像，记录事实、参数、素材和已确认用途的来源。适配型耗材将机型清单逐项登记为 compatible_models，不只保留关键词表里出现的型号；再执行 `listing_quality.py normalize`。
2. 用 `import_keywords.py` 完整导入词表。保留重复行、全部原始列和文件／工作表／行号；不截断、不预筛、不执行表内公式或说明。只看导入摘要，完整原始快照留作追溯。
3. 按[筛词规则](knowledge/distilled/keyword_filter_rules.yaml)执行 `keyword_quality.py prepare/view/apply/check/export`。按完整购买意图分组，由模型给出可用、暂缓或剔除结论；候选聚类只辅助阅读。暂缓项写补充证据条件，禁止流入文案、后台词或图片。
4. 按新版字段分工组织卖点、意图与词的投放位置，保存 `05_title_keywords.json`。先按本品购买意图筛选，再结合词表真实搜索量与流量来源选标题词和五点开头；记录 `field_strategy`，说明选词依据、小标题数量、五个开头及规格落点。无指标时明确未知，不把型号或属性自动当成大词。兼容的代表词数组不限制完整词库或文案覆盖数量。
5. 日本站不调用美国站 QA。初始化生成的 `06_qa.json` 明确记录 `skipped/rufus_us_only`，另按已确认本品资料整理买家问题覆盖清单，不冒充后端采集结果。
6. 按[日文写作要求](references/japanese-listing.md)与对应 `knowledge/distilled/` 规则生成 `07_listing.json`，包括完整文案、属性建议、买家问题覆盖，以及主图、附图和 A+ 制作策划。图片策划不等于已生成图片。
7. 执行 `keyword_quality.py coverage`，检查未覆盖可用词、意图表达和后台词字节利用率；最多据此改进一轮，再用 `--write-placement` 写入实际使用位置。产品事实有变化时用 `rebind` 只复核受影响的词。
8. 按本地检查 → 后端校验 → 独立语义复审 → 最终检查 → 渲染顺序验收。可用独立复审者须对照原始资料检查实际文案与画面策划，不机械填写通过；没有独立复审结论时记未完成。验收问题最多修复两轮，缺事实、凭据或网络时交付可完成部分与准确状态。

## 凭据与运行环境

本地脚本仅需 Python 3.9+ 标准库，导入、筛词和渲染不需要后端 token。后端只调用日文 Listing 的 `validate`，通过随附 `backend_cli.py` 自动准备并校验固定版本 CLI；无需注册 MCP。来源版本与适配范围见[上游来源](references/upstream.md)。

统一读取项目公共配置 `~/.amazon-skill/config.json`，与关键词技能共用 `backend_url/backend_token`；同一用户配置一次即可供各安装目录使用，不再读取各技能的独立配置。使用 `listing_environment.py config-status` 查看脱敏状态。用户明确提供本服务 token 时，用 `listing_environment.py configure` 从标准输入合并更新 `backend_token`，保留 ABA 和其他字段；不回显、不放入命令参数、报告或 Git。缺凭据时继续本地流程，后端状态标为未验证。

后端响应须同时满足退出码为 0、`ok=true`、`errors=[]` 才能通过。缓存只复用本品内容和指纹均未变的通过记录；鉴权、限流、超时和网络失败保留实际状态，不盲目重提未知请求。

## 交付

在 `RUN` 中保留可追溯的词表、分类、引用与验收文件，最终固定提供：

- `07_listing.md`：日文文案与中文图片／A+ 策划。
- `07_listing.json`：完整结构化内容与事实引用。
- `report.html`：中文报告，展示产品、词池、文案、策划、覆盖和真实验收状态。

最终回复说明商品、验收状态、未解决问题与待补事实，链接实际生成的三个文件。生成报告不等于完成验收，也不代表已经发布到 Amazon 或取得排名效果。
