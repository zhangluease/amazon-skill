# 日本亚马逊 Listing

固定 JP／Japanese／ja；文案和图上文字用日语，策划、筛词说明和报告用中文。输入文件名不限，按内容和表头识别资料，保留真实来源。

## 核心规则

- 给定关键词默认正确、相关，不要求官网或说明书二次核验。只对原文无法解析、明确否定、用户禁用或资料直接冲突记录问题；泛词未表达的数值、性能和认证不推导。
- 标题 ≤75 字符，按「本品品牌 → 目标品番 → 完整部件名 → 适用对象／用途 → 兼容关系」组织。已确认品牌置首，目标品番紧跟品牌或直接置首。尽量把品牌、目标品番和完整部件名放在前 35–40 字符。已确认是兼容替换件时用「互換品」等准确措辞。未提供的本品品牌、目标品番或兼容性按缺口记录。
- Item Highlight ≤125 字符。先为实售数量和组成预留字数，正文选 3 个不同的已确认代表机型并补必要用途，成稿末尾用一个短段集中写组成与装数。资料不足或包装信息占用空间时按实减少机型。材质尺寸放五点正文，五点开头结合相关词。字符上限含空格，流量未知按相关性选词。
- 按耗材的选购依据组织五点：型号适配、规格适配或通用用途。编号按语义区分本品／替代件、适配对象和其他数值，不按固定前缀判断。已给定的适配对象须在五点完整列出，通常占 2–3 条，保留完整后缀。每条全文最多 250 字符，含型号、空格和标点。
- 五点默认按「型号与套装 → 性能与使用价值 → 适配 → 更换条件 → 品质与购买事项」组织，使用自然日语的「短主题：具体说明」。缺乏某主题依据时改用真实购买信息；长适配清单按字符预算分组，位置不足时优先合并或省略独立性能点。五条仍容纳不下时保留完整草稿并报告超限。
- 每次处理一个商品，数量、规格、包装、素材和事实引用限于本品。按真实资料写使用与更换信息，一次性耗材不套用清洗复用模板。

写作时读[日文字段规则](references/japanese-listing.md)；涉及适配、编号或选购条件时读[耗材规则](references/consumables.md)。数值配置在 [quality_policy.json](knowledge/quality_policy.json)，运营词位策略不表述为 Amazon 已公开的算法权重。

## 工作流程

按[命令流程](references/workflow.md)执行，[数据契约](knowledge/data_contract.md)定义文件结构：

1. 创建独立任务目录，建立本品画像并完整导入词表。
2. 根据完整语义安排编号与关键词角色；用工具登记适配事实、保存分类并导出词池。仅在需要时使用候选聚类。
3. 有给定竞品结论时用于选购买主题，以本品资料和可信关键词决定可写内容；不额外强制调研。生成 `listing.json`，包含文案、属性、买家问题覆盖、主图 1 张／附图 6 张／A+ 至少 5 张的制作策划。
4. 检查覆盖与实际词位，修正内容；完成本地检查、可用的后端校验和内容复核，再生成报告。改动后只重跑受影响检查。缺资料、凭据或网络时保留真实状态并交付已有结果。

图片交付为制作策划。生成后对照实际文案、适配名单与素材完成内容复核并填写依据，需要时使用独立复审者。

## 环境与交付

本地脚本只需 Python 3.9+ 标准库。后端仅调用日文 Listing 的 validate，配置读取 `~/.amazon-skill/config.json`；缺凭据不影响本地处理，后端记未验证。配置与固定版本 CLI 的使用见[命令流程](references/workflow.md#配置与旧任务)，来源见[上游适配](references/upstream.md)。

交付 `listing.md`、`listing.json`、`report.html`，保留任务目录中的来源与验收记录。最终回复链接三份实际文件，说明验收状态及未解决问题。报告生成不代表已通过验收或已发布到 Amazon。
