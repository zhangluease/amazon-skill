# 耗材适用与编号角色

适用于替换件、补充装、一次性用品及其他使用后需补充或更换的耗材。以下品类和表达仅用于解释选择方式，不提供任何商品事实，不限制编号格式或输入文件名。

## 先判断买家如何选购

| 选购依据 | 画像 compatibility_basis | 五点重点 |
| --- | --- | --- |
| 需要核对设备、容器或组件型号，例如墨盒、尘袋、替换刀头 | model | 全部明确适配对象分组列全，通常占 2–3 条；其余条目说明包装与必要规格 |
| 主要核对尺寸、接口、容量、等级，例如规格型密封圈、袋材或卷材 | specification | 说明给定的选择条件、尺寸对象和限制，不凭规格推导具体设备名单 |
| 不依赖对象型号，例如通用清洁布或垃圾袋 | none | 用途、规格、材质、数量、使用或存放，不强制适配清单 |

记录 compatibility_reason，解释依据。混合条件可在 facts／measurements 中同时表达；即使主要按规格选购，资料已给出的适配对象仍完整保留。包装尺寸不等于本体尺寸，容量不等于包装件数，接近的尺寸不等于兼容。通用耗材也不能擅自宣称所有设备或材料均适用。

## 按对象理解标识

同一个前缀、纯数字或同一个字符串可以因上下文而扮演不同角色。结合本品名称、原始字段标签、关键词完整修饰关系和本轮产品资料解释：

- `product_part`：正在销售的耗材、替换件或其可替代原件的型号／货号，不是所适用设备的型号。
- `compatible_model`：明确指向本品适配对象的标识；对象不限于整机，也可为容器、组件或其他产品。
- `other`：规格、数量、容量、版本、日期或其他不属于上述两个角色的内容；保留实际含义，不进入适配对象数组。
- `pending`：原文缺失或语义确实无法解析，须说明具体缺口。不能以「没查官网」为理由。

不根据编号前缀、字符数或是否带连字符判断角色，不把规格数值自动认作型号。给定关键词默认正确；角色理解只决定如何写入文案和事实，不重新评价其真实性、相关性或要求二次核验。

## 编号记录与登记

`prepare` 生成 `02_identifier_roles.json`。有明确产品字段的标识可预分配角色；其他含数字的候选只是阅读提示。模型填写 records 的 identifier、role、source_positions（02 原词数组的零基位置）和 reason，可添加纯名称／带空格／非拉丁文字标识。一个标识在不同行含义不同时拆成不同记录，同一行不重复分配。完整名称覆盖候选片段时无需再把片段当成另一台设备。

```json
{"identifier":"示例完整标识","role":"compatible_model","source_positions":[0],"reason":"该原词明确表示本耗材适用于此对象，依给定输入直接采用"}
```

保留工具生成的 raw_fingerprint 和 context_fingerprint；输入上下文变更时重新生成角色记录并重新解释，不能仅修改指纹表示已理解。已有任务可先 rebind 处理画像改动，备份旧角色记录后移出 RUN，再运行 register-models 生成当前上下文的候选，按当前资料重新填写并再次登记。执行 `keyword_quality.py register-models --run-dir RUN` 后，适配对象登记到 compatible_models confirmed 事实，并将对应关键词设为可用；已错误暂缓的旧结论保留初始记录和修正依据。未完成角色理解时工具报 incomplete，不会猜测适配关系。记录中引用的标识必须实际出现在对应原词中。

资料的来源名称（官网、竞品反查、联想等）不会取消用户给定词表的可信地位。只有明确否定、用户具体禁用或资料直接冲突才按原文记录问题。不能从共同编号推导全系列，不把图片或参考页面没有提供的兼容关系加入本品。

## 内容随耗材变化

数量单位按实际商品使用枚／個／本／袋／巻／組等；套装分别列各组成，不能把主耗材和配件相加当作耗材件数。更换、清洗、回收、保存、保质期与寿命只写给定依据支持的内容；一次性耗材不套用清洗复用模板。卫生、食品接触、抑菌、无菌、医疗用途、认证和原装／授权等声明不得从品类常识推导。

用户文件可任意命名。按文件内容识别输入角色，多文件与多工作表完整保留真实来源。RUN 内固定命名的 JSON／报告是内部协议；知识库 sources 中的历史文档名称只是规则来源元数据，不是用户必须提供的文件。
