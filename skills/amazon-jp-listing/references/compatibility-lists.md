# 适配型耗材：完整机型清单

当本品是替换滤网等依赖设备机型选购的配件／耗材时使用。这里的连续适配清单结构优先于通用的「每条回答不同购买问题」。缺少适配资料时，登记 compatible_models 的 unknown 空数组，明确待补资料并保留未完成状态；不能用泛卖点掩盖清单缺口。不把此结构强制用于没有机型适配需求的商品。

## 从资料建立清单

在 00 输入快照保留用户原清单、文件／图片位置；逐项核对后，按[数据契约](../knowledge/data_contract.md)写入本品 facts：

```json
{"fact_id":"fit-hd","field":"compatible_models","value":["HD-500A","HD-5016E4"],"group_label":"HD系","source_ref":"本品说明书：适配表第2页","status":"confirmed"}
```

这只是结构示例，不能作为任何商品的适配证据。每个字符串只有一个完整机型；不以 `HD-500A～HD-500F`、通配符、`HD-RXシリーズ` 或省略号代替逐项数据。保留型号字母、数字、连字符、后缀；OCR 造成的断字／混淆先核对原图，不能猜补。多个来源的重合型号可以在最终清单去重，但不能丢掉来源或把不同后缀合并。

confirmed 仅用于本品已确认关系；待确认和冲突项单独记 unknown／conflict，不混入上架文案，不宣称已确认清单涵盖全部资料。竞品详情、关键词表与参考截图只提供核对线索，不能单独证明本品兼容。若用户明确将附件指定为本品适配表，记录该指定及原件来源后再采用。

型号事实不依赖关键词搜索量，无须为了保留每个已确认机型先把它注册成流量词。关键词筛选仍约束前置搜索短语，不应因机型不在词表里而从兼容清单删除。其他商品的清单不能混入本品；多个商品分别建立独立任务。

## 五点组织

保留 5 条，长名单一般分配 2–3 条；短名单可用 1 条。按资料已有分组或机型系列整理，各组内保留可核对的原顺序。不要按所谓流量排序删掉长尾机型，也不要把同一清单重复堆满五条。

参考组织方式（是结构，不是可复制的商品文案）：

1. `【相关搜索词・対応機種①】` 第一组完整机型。
2. `【相关搜索词・対応機種②】` 第二组完整机型。
3. `【相关搜索词・対応機種③】` 其余完整机型；如果两组已列全，本条可用于包装／本品型号信息。
4. `【本品核心词・仕様】` 本品／替换件型号、真实材质、尺寸或包装内容；按已确认信息合并组织。
5. `【本品核心词・お手入れ】` 已有依据的清洗、维护及更换条件；缺资料时使用其他真实内容，不能编造周期。

标签尽量结合自然相关搜索词，可用 `対応機種①／②／③` 或系列名区分，允许适配主题连续占据多条。不强求三条清单必须用三个不同大词。每条 claims.fact_ids 引用该条所用的 compatible_models 事实；同一事实分散在多条时分别引用。不得将 `HD-5016E4` 缩成 `HD-5016`，也不能用“等”“系列通用”或范围隐藏缺失机型。

材质尺寸和必要使用信息仍须保留，在剩余条目中合理合并，不因列清单完全丢失。完整兼容信息必须在五点，不以长描、图片、A+ 或另外一个文件代替；这些位置可以补充，但五点仍须列全。

## 长度与验收

`quality_policy.json` 中普通文案的单条 250、合计 1250 字符为内部编辑预算。只对正确引用、已确认、有来源、适用于本品的 compatible_models 型号及紧随的清单分隔符单独计数；普通说明文字仍受预算约束。这不是全类目通用的平台字符上限，也不表示 Amazon 允许无限长度。

本地检查逐个比对完整型号，防止前缀误命中及只在长描出现；机型已出现却未引用对应事实也不能通过。超过普通预算的清单保留原文并给 `compatibility_list_length` 提示，后端 payload 不截断、不省略、不改写。真实类目／后端若拒绝长度，保留完整稿和实际失败状态，列明冲突；不能为了通过而静默删型号、伪造成功或将完整清单移出五点。

语义复审的 `compatibility_models` 项须对照本品原始资料检查：来源清单是否完整录入画像、五点是否漏项或多写、后缀与分组是否正确、是否与本品一致、关键词开头是否自然。机器核对范围与完整字符串，不证明硬件兼容性本身。没有适配需求的商品说明理由后可记 not_applicable；已有适配资料但尚未核实不能直接记不适用。
